# light-view M7 설계: 탐색기에서 HEIC 보기, 두 가지 설치 방식

- 날짜: 2026-10-29 (스파이크 뒤 개정)
- 바탕: [light-view 설계](2026-10-26-light-view-design.md), M6까지 완료(main, v0.1.1)
- 표시: **[사용자 결정]**은 사용자가 정한 것, **[설계자 판단]**은 대화 중 제가 정하고 사용자가 받아들인 것, 표시 없는 세부는 빌더 재량.

## 1. 무엇을, 왜

Windows는 HEIC/HEIF 썸네일을 그리려면 Microsoft의 유료 HEVC 확장이 필요하다. 그래서 아이폰 사진 폴더를 탐색기로 열면 사진 대신 빈 아이콘만 보인다. light-view가 그 자리를 채워, 아이폰 사진도 탐색기에서 JPEG처럼 보이게 한다. **[사용자 결정: 썸네일과 미리 보기 창 둘 다]**

스파이크(Task 1) 결과, Windows의 격리된 썸네일 호스트는 HKCU에만 등록한 처리기를 읽지 않는다(`0x80040154`). 그래서 설치를 두 가지로 나눈다. **[사용자 결정: 사용자별 설치와 관리자(모든 사용자) 설치를 고를 수 있게]**

## 2. 설치 방식 **[사용자 결정]**

| | 사용자별 (기본) | 모든 사용자 (관리자) |
|---|---|---|
| 권한 | 없음, UAC 없음 | 관리자, UAC |
| 폴더 | `%LOCALAPPDATA%\Programs\light-view` | `C:\Program Files\light-view` |
| 등록 | HKCU | HKLM (PC 전체) |
| 썸네일·미리 보기 | 탐색기 안에서 실행(`DisableProcessIsolation=1`) | Windows 기본 격리 호스트에서 실행 |
| 자세히 탭(해상도·찍은 날짜·카메라) | 없음 | 있음 |
| AppContainer 폴더 권한(icacls, M5 R2) | 지금처럼 부여 | 필요 없음(Program Files는 이미 읽기 가능) |

- 설치 첫 화면에서 고른다(Inno Setup `PrivilegesRequiredOverridesAllowed=dialog`). 기본 선택은 사용자별.
- 두 방식 모두 사진 해석(C 코드)은 샌드박스 작업자에서만 한다.
- 설정 파일은 두 방식 모두 사용자마다 `%APPDATA%\light-view\settings.toml`.
- 서명은 v1.0 릴리스 때 받는다. 그전에는 관리자 설치에서 UAC 창에 "알 수 없는 게시자"가 나온다(README에 적는다).

## 3. 목표, 비목표, 반목표

### 목표
- **썸네일:** 탐색기의 목록·큰 아이콘·갤러리 보기에서 HEIC/HEIF가 실제 사진으로 보인다(두 방식 모두).
- **미리 보기 창:** 탐색기 "미리 보기" 창에서 HEIC/HEIF가 크게 보인다(두 방식 모두, 사용자별은 Task 1b 스파이크로 확인).
- **자세히:** 관리자 설치에서 파일 속성 "자세히" 탭과 탐색기 자세히 보기에 가로×세로, 찍은 날짜, 카메라 제조사·모델. 위치 정보는 내보내지 않는다.

### 비목표 **[설계자 판단]**
- JPEG·PNG·GIF·BMP·WebP(Windows가 이미 그린다), AVIF·RAW.
- 포터블판 등록.
- 사용자별 설치의 자세히 탭(Windows가 HKLM만 읽는다).
- 속성 쓰기, 미리 보기 창 안의 확대·넘기기.

### 반목표 (돌아가도 이러면 실패)
- 이상한(악의적인) HEIC 파일 하나로 탐색기가 죽거나 멈춘다.
- HEVC 디코더(C 코드)가 탐색기 프로세스·검색 색인기·샌드박스 밖에서 돈다.
- 사진 20장 폴더의 썸네일이 몇십 초씩 걸리거나 그동안 탐색기가 버벅인다.
- 원본 사진을 고치거나 사진 폴더에 파일을 새로 만든다.
- 제거한 뒤 탐색기 등록이 남거나, 관리자 설치 제거 뒤 Windows 원래 자세히 처리기가 돌아오지 않는다.

## 4. 안전 원칙 **[설계자 판단]**

- **C 코드(libheif·libde265)는 샌드박스 작업자에서만.** 셸 확장은 순수 Rust이고, 사진 바이트를 작업자에 넘겨 픽셀만 받는다. 작업자는 M2–M6과 같은 격리(Job 안에서 태어남, 낮은 무결성, 되면 AppContainer, win32k 잠금, 자식 프로세스 금지, 메모리 상한).
- **사용자별 설치에서는 썸네일 처리기가 탐색기 안에서 돈다.** 그래서 탐색기 쪽 코드는 최소로: 스트림을 상한까지 읽고, 작업자를 띄우고, 받은 픽셀로 HBITMAP을 만드는 것까지. 파싱·디코딩은 하지 않는다. 모든 진입점은 `catch_unwind`로 패닉을 막고, 큰 할당은 상한 안에서만.
- **자세히(속성) 처리기는 작업자를 띄우지 않고 디코딩도 하지 않는다.** 검색 색인기(SYSTEM 권한)와 탐색기 안에서 불리므로, HEIF 컨테이너 파싱(기존 순수 Rust `heif_edit`)과 EXIF 읽기(kamadak-exif)만, 앱과 같은 크기·깊이 상한으로 한다. 관리자 설치에만 등록하고 DLL은 Program Files에 있어 일반 사용자가 바꿀 수 없다.
- 파일 읽기는 넘겨받은 스트림으로만. 경로를 직접 열지 않는다. 읽는 바이트는 앱의 HEIC 파일 상한 이하.
- 어떤 실패든 "썸네일 없음"/"속성 없음"으로 끝낸다.

## 5. 동작

- **썸네일:** 요청 크기 이하로. HEIC 내장 미리 보기 이미지가 요청 크기 이상이면 그것을, 아니면 본 이미지를 줄여서. 방향 적용, sRGB.
- **미리 보기 창:** 창에 맞춰 줄여 그린다(확대 없음). 여러 장을 빠르게 고르면 마지막 것만.
- **자세히:** 가로×세로(돌린 뒤), 찍은 날짜(EXIF DateTimeOriginal), 카메라 제조사·모델.
- **속도:** 썸네일 한 장 300 ms 이내(내장 이미지면 100 ms 안팎). 스파이크에서 작업자 경로는 70–80 ms(디버그 빌드, 두 번째 호출부터).

## 6. 설치·업데이트·제거

- 확장 DLL은 버전마다 다른 이름(`lv-shell-<version>.dll`)으로 설치하고 등록을 새 파일로 바꾼다. 쓰던 옛 DLL은 `RunOnce`(사용자별은 HKCU, 관리자는 HKLM)로 다음 로그인 때 지운다. **업데이트·제거 때 탐색기를 닫거나 다시 시작하지 않는다.**
- 관리자 설치는 `.heic`·`.heif`의 원래 자세히 처리기 값(Windows `PhotoMetadataHandler` 등)을 설치 때 저장해 두고, 제거 때 되돌린다.
- 한 PC에 두 방식이 함께 깔리는 경우: 사용자별 등록(HKCU)이 그 사용자에게 우선한다. 관리자 설치 화면에서 이미 사용자별로 깔려 있으면 알려 준다(제거는 강제하지 않음).
- 썸네일 캐시는 지우지 않는다(README에 비우는 법).

## 7. 사용자 결정 기록

- 2026-10-29: 썸네일과 미리 보기 둘 다.
- 2026-10-29: 사용자별·관리자 설치를 고르게 한다. 사용자별은 탐색기 안 실행으로 썸네일을 켜 두고, 관리자 설치에는 자세히 탭을 넣는다.
- 2026-10-29: 서명은 v1.0 릴리스 때.

## 8. 빌더 재량

- 크레이트 구성(`lv-shell` cdylib, 작업자 시작 코드 공용 크레이트), COM 구현(`windows` `implement`).
- 작업자 요청 형식, 내장 이미지 선택 규칙, 미리 보기 그리기 방식(GDI/Direct2D).
- 시험: COM 객체를 테스트에서 직접 만들어 부르는 단위 테스트. 실제 탐색기·관리자 설치 확인은 사용자 확인 항목.
